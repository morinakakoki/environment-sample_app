# 面接 60秒トレーナー

転職面接の練習用。質問を1問出して60秒を計り、話し終わったら自分でセルフチェックして、
結果を1行のログにするだけのアプリ。**出題・計時・セルフチェック・記録しかやらない。**

`index.html` の1枚だけで動く。Claude Artifacts にそのまま貼れる。

## 質問バンク

`interview-question-bank.json` に **108問**（A〜K の11カテゴリ）が入っていて、
`index.html` にも埋め込み済み。そのまま使える。

| | カテゴリ | 問数 | |
|---|---|---|---|
| A | 転職理由・軸 | 12 | 深掘り対象 |
| B | キャリアの一貫性 | 10 | 深掘り対象 |
| C | 実績・再現性 | 12 | 深掘り対象 |
| D | 志望動機・企業理解 | 12 | 深掘り対象 |
| E | 強み・弱み | 8 | |
| F | 対人・チーム | 8 | |
| G | 数字・マネジメント | 8 | |
| H | 懸念・空白期間 | 12 | 深掘り対象 |
| I | 条件・待遇 | 7 | |
| J | 将来像 | 7 | |
| K | 逆質問 | 12 | 計時なし |

「深掘り対象のみ」モードは A・B・C・D・H の **58問**。
出典タグは 頻出 / 深掘り / 圧迫 / 一次 / 二次 / 最終 / 条件確認 / 定番 / 踏み込み。

**この質問は叩き台。** 自分の職歴・応募先に合わせて足したり削ったりして使うこと。
特に H（懸念・空白期間）と I（条件・待遇）は、実際に自分が聞かれそうな形に
書き換えたほうが練習になる。

### 質問を編集したら

`interview-question-bank.json` を直して、埋め込み直す:

```
python3 embed-bank.py interview-question-bank.json
```

`index.html` の `/* BANK:START */` 〜 `/* BANK:END */` の間だけが書き換わる。
手で貼り替えてもよい。質問文・ID・カテゴリは JSON の値をそのまま出す
（トリムも変換もしない）。

`__sample__: true` を JSON に入れておくと、アプリ上部に「サンプルデータで
動作中」の警告バナーが出る。差し替え途中の目印に使える。

### 想定しているJSONの形

```jsonc
{
  "meta": {
    "deepDiveCategories": ["A", "B", "C", "D", "H"],
    "checkCriteria": ["結論が最初", "60秒以内", "軸と矛盾なし", "具体あり", "前提共有"],
    "logFormat": "| 日付 | ID | 結果 | 崩れた基準の番号 | 次にやること |"
  },
  "categories": [{ "id": "A", "name": "転職理由・軸" }],
  "questions": [{ "id": "A-01", "category": "A", "text": "…", "source": "…" }]
}
```

キー名が多少違っても読める（実際に検証済み）:

| 揺れ | 対応 |
|---|---|
| `categories` がオブジェクトマップ `{"A":"転職理由・軸"}` | 読める |
| `questions` が `items` / `bank` | 読める |
| `text` が `question` / `q` / `body` | 読める |
| `category` が `categoryId` / `cat` / `group` | 読める |
| `source` が `sourceTag` / `tag` / `origin` | 読める |
| `checkCriteria` が `[{no, label, note}]` のオブジェクト配列 | 読める（`note` は補足として表示） |
| `categories` キーが無い | ID の先頭英字からカテゴリを推測 |
| ID がハイフン無し（`A01`） | 読める |
| `meta.checkCriteria` が無い | 仕様の5項目を既定値として使う |
| `checkCriteria` が `{"1":"…"}` のオブジェクトマップ | 読める |
| `questions` がオブジェクトマップ / `categories[].questions` にネスト | 読める |
| `deepDiveCategories` が `"A・B"` のような文字列 | 区切って読む |
| `category` がオブジェクト `{id,name}` | `id` を使う（`[object Object]` にしない） |
| 基準に `index: 0` のような0始まり番号 | 0始まりとみなして +1（番号が重複したら振り直す） |
| `logFormat` の列順が違う / 区切り行 `|---|` 付き / 非文字列 | 見出しを読んで対応する列に入れる |
| 質問文に `< > & "` が含まれる | 文字としてそのまま表示（エスケープ済み） |
| `次にやること` に `|` を入れた | `\\|` にエスケープして表を壊さない |

どの形でも**例外を投げない**ことを優先している（白画面にしない）。

`meta.logFormat` は**見出しを読んで**列を決める。`| ID | 結果 | 次にやること | 崩れた基準の番号 | 日付 |`
のように順番が違っても、中身が入れ替わらない。

## 使い方

1. **モードを選ぶ** — カテゴリ別（A〜K）／全体ランダム／深掘り対象のみ（`meta.deepDiveCategories`）
2. **開始** — 60秒タイマー。残り10秒で色が変わる（琥珀）。0秒で赤に変わって点滅し、超過分をカウントアップする。**音は鳴らさない**
3. **答え終わった** — セルフチェック画面。崩れた基準にだけチェックを付ける。60秒を超えていたら「60秒以内」は自動でチェックが付く（外せる）
4. **判定** — **60秒以内**かつチェック0個なら🟢、それ以外は🟡。「言えなかった」ボタンで🔴
   （自動チェックを手で外しても、実測が60秒を超えていれば🟢にはならない）
5. **次にやること**を1行入れて（省略可）、ログ行をタップでコピー
6. **次の問題へ**。ログは画面下に溜まり、まとめてコピーできる

K系（逆質問）だけはタイマーを使わず、「この会社に対して言えるか」を🟢/🔴で判定するだけ。

## 制約として守っていること

- **保存APIを一切使わない** — `localStorage` / `sessionStorage` / `indexedDB` / Cookie は
  コード中に存在しない。状態はメモリ内だけ。閉じると消えるので、記録はコピーして外に出すこと
- **外部fetchなし** — 質問データはHTMLの中。`fetch` / `XHR` / `WebSocket` / `sendBeacon` は不使用。
  ネットワークを止めても全機能が動く
- **フレームワーク・外部ライブラリなし** — 素のJS
- **スマホ縦画面前提** — 1カラム、タイマーは大きく、ボタンは全部44px以上

唯一の外部通信は Google Fonts（`fonts.googleapis.com` / `fonts.gstatic.com`）。
ページを開いた事実と IP・UA が Google に渡る。落ちても字が変わるだけで動作に影響はない。
**「次にやること」の入力欄だけは Web フォントを使わない。** Google Fonts は
unicode-range でサブセット分割されているため、珍しい文字を打つと新しいサブセット取得要求が
飛び、入力した文字種が外部に漏れうるため。同じ理由で入力欄は
`spellcheck="false" autocomplete="off"` を指定し、ブラウザのクラウド校正やオートフィルにも渡さない。

外部通信を完全にゼロにしたい場合は、`index.html` 冒頭の `<link>` 3行を消せばよい。
端末内のフォントで描画され、機能はすべてそのまま動く。

## セキュリティ

質問バンクは**信頼できない入力として扱っている**（他人が作った JSON を貼る運用があるため）。

- 描画は全経路で `esc()`（`& < > " '`）を通す。質問文・ID・カテゴリ名・出典タグ・
  基準ラベル、および「次にやること」の入力を、テキスト・属性値の両文脈で検証済み
- `embed-bank.py` は `< > & /` を JSON エスケープに置き換えてから埋め込む。
  これで `</script>` / `<!--` / `<!--<script>`（script data double escaped）/
  `/* BANK:END */` の偽装がいずれも成立しない。U+2028・U+2029 もエスケープする。
  埋め込み後にマーカーの一意性と `json.loads(payload) == 元JSON` を検証してから書き込む
  （エスケープは JSON の `\uXXXX` 表記なので、デコードされる値は一字も変わらない）
- JSON 由来の文字列をキーにする辞書は `Object.create(null)` を使う。
  `toString` や `constructor` というカテゴリIDで組み込みプロパティを拾わない

`node test/security.js` が、悪意ある質問バンク9種（マーカー偽装・`</script>`・
`<!--<script>`・`<img onerror>` など）を埋め込み1〜3回で流し込み、
任意JSが実行されないこととアプリが起動し続けることを確認する。

## 動作確認

```
npm i playwright
node test/test.js       # 本編の通し操作
node test/variants.js   # JSONの形が違う15ケース
node test/security.js   # 悪意ある質問バンクからの攻撃9種
```

`test/wrap.js` は Artifacts の公開時ラッパー（doctype / head / リセットCSS）を再現する。
テストはこれを噛ませて、実際に配信される形の HTML を検証している。

（`npm i playwright` が要る。`CHROME_PATH` で Chromium の場所を指定できる。）
