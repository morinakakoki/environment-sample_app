# データ基盤 復習クイズ

GCP データ基盤ポートフォリオを作りながら、**作った方式を言葉で説明できる状態にする**ための復習クイズ。

**方式や機能を作ったら、その方式の問題が増える。** これが基本の形です。
問題数の少ない方式は、まだ言葉にできていないところなので、そこが次に足す場所になります。

- `index.html` 1枚で完結（CSS / JS インライン、ビルド不要、依存パッケージなし）
- 問題は **Notion の「復習クイズ 問題ストック」** から読む。ページに埋め込んだ分と合わせて出題する
  （**Notion 連携はアーティファクト版だけ**。ローカルサーバで開いた場合は埋め込み分のみ）
- 学習記録は `localStorage` が「正」で、**Notion と同期**（端末をまたいで引き継がれる。これもアーティファクト版のみ）
- 全48問に**出典**（公式ドキュメントの URL）付き
- **LLM API は使わない** → **ランニングコスト 0 円**

## 1. 起動

`fetch()` はブラウザのセキュリティ制限により `file://` では動きません。**このフォルダでローカルサーバを立てて**ください。

```bash
cd quiz
python3 -m http.server 8000
# → http://localhost:8000 を開く
```

Node 派なら:

```bash
cd quiz
npx serve .          # または npx http-server .
```

> `index.html` をダブルクリックで開いてしまった場合も、エラー画面から `quiz-data.json` を手動で選んで読み込めます（動作確認用の逃げ道。普段はローカルサーバ推奨）。

スマホで解きたいときは、PC と同じ Wi‑Fi につないで `http://<PCのローカルIP>:8000` を開きます。
`http.server` は全インタフェースで待ち受けるので、**カフェやコワーキングの共有 Wi‑Fi では
使わないでください**（同じネットワークの全員が `quiz/` の中身を読めます）。外出先ではこの下の
アーティファクト版を使ってください。

### スマホで使うなら：アーティファクト版

**https://claude.ai/code/artifact/961a5f90-b530-4a93-8925-de6cdb85e282**

同じアプリに問題データを焼き込んだ版を公開してあります。**非公開（自分だけ）・無料**で、
スマホでこの URL を開くだけで使えます。ローカルサーバも Wi-Fi も要りません。

アーティファクトは単独の HTML ページなので、隣の `quiz-data.json` を `fetch` できません。
そのため問題データを HTML に埋め込んだものを `build-artifact.mjs` で生成しています。

```bash
cd quiz
node build-artifact.mjs      # quiz-data.json を index.html に埋め込んで artifact.html を作る
```

**ふだんは上のコマンドを使う必要はありません。** アプリの「問題を追加」画面から
保存すれば、アーティファクト版はその場で更新されます。

このコマンドが要るのは、**アプリ本体（見た目や機能）を変えたとき**だけです。
そのときは `node build-artifact.mjs` のあと、Claude に「artifact.html を再発行して」と頼んでください。

なお、アプリ上で追加した問題はアーティファクト側にしか入りません。リポジトリの
`quiz-data.json` にも残したい場合は、**ローカル版の**「問題を追加」画面に同じ JSON を貼って
コピー機能を使う（アーティファクト版には保存ボタンしか出ません）か、ステップ2' の直接編集を
使ってください。

学習記録はアーティファクト固有のドメインの `localStorage` に入るため、**再発行しても消えません**。
ただし PC 版とアーティファクト版では記録は別々です。

## 2. ファイル構成

```
quiz/
├── index.html          … アプリ本体（これ1枚。触るのは見た目を変えたいときだけ）
├── quiz-data.json      … 問題データ（毎日ここに追記していく）
├── build-artifact.mjs  … アーティファクト版を生成するスクリプト

│   └── runall.sh       … cd quiz/tests && sh runall.sh で全部走る
└── README.md           … これ
```

`index.html` は2通りの動き方をします。`<script id="quizData">` が埋め込まれていればそれを使い
（アーティファクト版。`window.QUIZ_DATA` でも可）、なければ `quiz-data.json` を `fetch` します
（ローカル版）。
問題データの持ち方が違うだけで、中身は同じ1つのコードです。

## 3. 出題モード

| モード | 内容 |
| --- | --- |
| **全範囲 10問** | `間違い → そろそろ忘れる頃 → 未挑戦 → 済み（正答率の低い順）` に並べて先頭 10 問 |
| **方式別** | 方式設計書の方式ごと。**「run_mart を足したから処理方式を復習する」**という使い方。方式ごとの問題数と正答率がホームに出る |
| **章別** | 基礎知識ノートの章ごと。並び順は同じく間違い優先 |
| **間違いのみ** | 「直近に解いて不正解だった」問題だけ。正解できたらこのリストから自動で外れる |
| **そろそろ復習** | 正解してから間隔が空いた問題だけ。下の「忘れる前に出す」を参照 |
| **最近追加された問題** | `addedAt` の新しい順に 10 問。同じ日の中では**未挑戦の問題から**出す（間違えた問題で枠が埋まって、新しい問題が出てこなくなるのを防ぐため）。その日追記した分がそのまま出るので、寝る前の復習に使う |

### 忘れる前に出す（間隔反復）

間違い優先だけで並べると、**一度正解した問題は次に間違えるまで永久に「済み」**になります。
3週間前に1回当てただけの問題と、今日3回続けて当てた問題が同じ扱いになり、忘れかけの問題が
出てきません。そこで、正解が続くほど次の出題までの間隔を伸ばしています。

| 連続正解 | 1回 | 2回 | 3回 | 4回 | 5回 | 6回以上 |
| --- | --- | --- | --- | --- | --- | --- |
| 次に出るまで | 3日 | 1週 | 2週 | 1か月 | 2か月 | 4か月 |

間隔を過ぎた問題は「そろそろ復習」に出てきて、全範囲でも間違いの次に優先されます。
**間違えると連続回数は 0 に戻り**、また3日後から始まります。
学習の記録の**定着率は、この間隔を過ぎた分を外して数えます**（だから放っておくと下がる）。

### 説明モード

4択は「選択肢を見て正解を**認識**できるか」を測ります。面接で問われるのは、何も無いところから
**説明を組み立てられるか**です。この2つは別の能力で、4択で満点でも説明できないことは普通に
起きます。

ホームの「**説明モードで解く**」をオンにすると、どのモードでも**選択肢を隠して**出題します。
頭の中で（できれば声に出して）説明してから「答えを見る」を押し、解説と突き合わせて
**説明できた / できなかった**を自分で申告します。

- 記録は 4択とは**別枠**（`explain`）に入るので、4択の正答率は濁りません
- 学習の記録に「説明できた」率が出ます
- **「4択では取れるのに説明できなかった」問題**があると、その方式名を名指しで出します。
  そこが次に方式設計書へ戻るべき場所です
- Notion にも記録されますが、明細に `%` の印を付けて送るので、取り込むときに
  4択の成績（`stats`）ではなく `explain` に入ります。**別の端末で説明したぶんも合流し、
  4択の正答率と「そろそろ復習」の間隔は動きません**

#### 自分の説明を書き残す

説明モードの画面には**メモ欄**があります（任意）。書いて「答えを見る」を押すと保存され、
面接前チェックリストに解説と並べて出ます。

前に書いた文は、**答えを見るまで表示しません**。先に見えてしまうと、思い出せていないのに
読んで「言えた」と申告してしまい、説明モードの意味がなくなるためです。答えと一緒に出るので、
そこで見比べてください。保存は 1問につき 1件（上書き）、上限 1000 字です。

> メモ欄にカーソルがある間は <kbd>Enter</kbd> などのキー操作は効きません（改行として入ります）。
> 書き終わったら「答えを見る」を押してください。

### 面接前チェックリスト

ホームの「**弱点をまとめて見る**」から開きます。**説明できなかった問題**を先に、次に
**直近で間違えた問題**を、答え・解説・自分の説明つきで並べます。出題はしません。
面接や勉強会の直前に、ここだけ読み返すための画面です。

「テキストでコピー」で Markdown として写せるので、Notion に貼って持ち歩けます。

### 出題から外す

問題を解いたあとに出る「**この問題は今後出さない**」を押すと、その問題はどのモードにも
出なくなります（総数・正答率・カバー率の分母からも外れます）。押したセッションの並びは
崩さないので、`n / 10` はそのままです。

アーティファクト版は問題データが埋め込みなので、間違った問題や古くなった問題を
**消す手段がありません**。せめて「もう出さない」を選べるようにしてあります。
外した問題はホームの「データ」に一覧で出て、いつでも戻せます。

---

**選択肢は出題のたびにシャッフルされます。** 元の38問は正解の68%が2番目に集中していたため、
そのままだと「迷ったらB」で当たってしまうためです。位置ではなく中身で覚えられます
（この都合上、解説に「選択肢2が誤り」のような**位置での参照は書かないでください**。
内容で「〜という記述は誤り」と書けば並びが変わっても壊れません）。

**長さでも当てられないようにしてあります。** シャッフルは位置しか直せません。当初は
正解だけが説明的な長文で誤答が短い言い切りだったため、**「一番長い選択肢を選ぶ」だけで
83%正解できる**状態でした。誤答を正解と同じ長さ・同じ具体度に書き直し、いまは全48問で
差が8字未満（平均6字）に収まっています。**問題を足すときも、4つの選択肢の長さを
そろえてください。** `bias.mjs` がこれを見ていて、崩れるとテストが落ちます。

解答すると即座に正誤・解説が出ます。解説には必ず **章（chapter）と 理解度表の番号（tag）** が付くので、そのまま基礎知識ノートの該当箇所に戻れます。

結果画面には **章別スコア** と **「戻る章」**（間違いのあった章を正答率の低い順に、見直すべき tag 付きで）が出ます。

PC ではキーボードでも解けます: <kbd>1</kbd>〜<kbd>4</kbd> で解答、<kbd>Enter</kbd> / <kbd>Space</kbd> で次へ。

## 4. ✅ 新しい問題の追加手順

### 考え方：日付ではなく「方式」で増やす

問題は「今日やったこと」ではなく、**方式設計書のどの方式を作ったか**に紐づけます。
新しい方式や機能を組んだら、その方式の問題が増える。これが基本の形です。

```
run_mart を足した   →  処理方式 の問題が増える
as-of ジョインを実装 →  データ方式 の問題が増える
カスタム割り当てを設定 →  コスト方式 の問題が増える
```

ホームの**「方式別に解く」**に、方式ごとの問題数と正答率が出ます。
**問題数が少ない方式は、まだ言葉にできていないところ**です。そこが次に足す場所になります。

現在の方式は8つ（方式設計書の区分）。`method` に新しい方式名を書けば、
**コードを触らずにその方式が増えます**。

| 方式 | 問題数 |
| --- | ---: |
| 構成・前提 | 7 |
| 処理方式 | 4 |
| データ方式 | 9 |
| 認証・権限方式 | 5 |
| 運用・監視方式 | 5 |
| コスト方式 | 7 |
| IaC方式 | 6 |
| 設計判断 | 5 |
| **合計** | **48** |

`chapter`（基礎知識ノートの章）と `method`（方式設計書の方式）は**別の軸**です。
前者は知識の在りか、後者は実装の在りか。どちらからでも辿れます。

### 足す道は3つ

**Notion に足すのが一番ラク**です。

> **Notion 連携が動くのはアーティファクト版だけです。** `window.claude` というランタイムが
> claude.ai 側にしか無いためで、`python3 -m http.server` で開いたローカル版では Notion を
> 読みに行かず、画面にも何も出ません（エラーではなく「その機能が無い」状態）。
> ローカルで問題を増やしたいときは B か C を使ってください。

| 方法 | 手間 | 反映 |
| --- | --- | --- |
| **A. Notion に行を足す** | 貼り付け不要 | 次に**アーティファクト版**を開いたとき |
| B. アプリに JSON を貼る | 貼り付け1回 | その場で保存 |
| C. quiz-data.json を直接編集 | ファイル編集＋再ビルド | 再発行後 |

### A. Notion に足す（おすすめ）

**復習クイズ 問題ストック**（Notion のデータベース）に行を追加するだけです。
Claude のプロジェクトでこう頼めば、そのまま書き込まれます。あなたは何も貼りません。

```
run_mart を足して raw → staging → mart の順序制御を時刻ずらしでやった。
処理方式の問題を3問、復習クイズ 問題ストックに追加して。
```

**「今日やったこと」ではなく「どの方式に何を足したか」**で頼むのがコツです。
そう頼むと `方式` 列が埋まり、アプリの「方式別に解く」に積み上がっていきます。

列は `問題` / `章` / `タグ` / `方式` / `選択肢A`〜`選択肢D` / `正解`（A〜D）/ `解説` /
`出典` / `追加日`。**列名は変えないでください。**アプリが名前で参照しています。

`選択肢` に空欄がある行、`正解` が未設定の行は読み込まれません（誤った正解を
教えてしまわないように、黙って通さず件数を画面に出します）。

Notion が読めないとき（接続切れ・未許可など）は、原因ごとの直し方を画面に出したうえで、
**埋め込みの48問はそのまま解けます**。Notion が落ちてもクイズは止まりません。


### ステップ 2 —（推奨）アーティファクト版のアプリに貼る

アーティファクト版を開いて **ホーム → データ → 「問題を追加」** に JSON を貼り、
「内容を確認」→「この内容で保存」。**それだけで永久保存され、URL も変わりません。**
ファイルの編集も、再ビルドも、再発行の依頼も要りません。

保存前に、追加される問題数・章の内訳・新しい章かどうか・タグが表示されます。
`id` が既存とかぶっている問題や壊れた JSON は、この段階で弾かれます。
**`id` は省いても構いません。**その場合は今の最大 id の続きを自動で振るので、
Claude に「id は何番から」と伝える必要はありません。
問題文が既存とほぼ同じ場合も警告が出ます（作り直したときに気づけるように）。

新しい章をタイトルごと足したいときは、こう貼れば章名も一緒に登録されます。

```json
{ "chapters": { "8": "ストリーミングと監視" },
  "questions": [ { "id": 39, "chapter": 8, "tag": "#21", "...": "..." } ] }
```

### ステップ 2'（別法）— quiz-data.json に直接貼る

`quiz-data.json` は **ただの JSON 配列**です。末尾の `]` の直前に、カンマ区切りで貼り付けます。

```jsonc
[
  { ...既存の問題... },
  { ...既存の問題... },          // ← ここのカンマを忘れずに
  {"id":39,"chapter":3,"tag":"#11","q":"…","options":["…","…","…","…"],
   "answer":2,"explanation":"…","addedAt":"2026-09-01"}
]
```

ローカル版（`python3 -m http.server` で開いた場合）の「問題を追加」画面では、
その場で保存する代わりに **追記後の `quiz-data.json` 全文をコピー**できます。
貼り替えれば、カンマの付け忘れなどの事故なく更新できます。

### ステップ 3 — リロードして「最近追加された問題」で解く

コードの変更は一切不要です。ブラウザを再読み込みすれば、ホームの総問題数と章別リストが自動で増えます。

> **貼り付けミスの検知**: JSON が壊れているとエラー画面が出ます。個々の問題の形式ミス（`options` が1つしかない、`answer` が範囲外 など）はその問題だけスキップされ、ホームに「読み込めなかった問題が N 件あります」と出ます（詳細はブラウザのコンソール）。全体が巻き込まれて壊れることはありません。

追記後に構文だけ確かめたいときは:

```bash
python3 -m json.tool quiz-data.json > /dev/null && echo "JSON OK"
```

## 5. quiz-data.json の形式

トップレベルは**問題オブジェクトの配列**です。

| フィールド | 型 | 必須 | 説明 |
| --- | --- | :-: | --- |
| `id` | number \| string | 任意 | 一意な識別子。**学習履歴はこの id で紐づく**ので、一度公開した問題の id は変えないこと。省略すると問題文から自動生成します |
| `chapter` | number | ○ | 章番号（1–7）。基礎知識ノートの章に対応 |
| `tag` | string | ○ | 理解度表の番号。`"#12"` 形式（`"12"` と書いても `#` を補います） |
| `q` | string | ○ | 問題文 |
| `options` | string[] | ○ | 選択肢。**4つ**が基本（2〜6 まで動きます） |
| `answer` | number | ○ | 正解の**0始まりインデックス**。`0` が A、`3` が D |
| `explanation` | string | ○ | 解説。解答後に chapter / tag と一緒に表示されます |
| `method` | string | 推奨 | **方式設計書のどの方式か**（`処理方式` など）。「方式別に解く」の軸。新しい方式名を書けばコード変更なしで増えます |
| `source` | string | **推奨** | 根拠にした**公式ドキュメントの URL**。解説の下と結果画面にリンクとして出ます。`http(s)://` 以外はリンクにしません |
| `addedAt` | string | ○ | 追加日 `"YYYY-MM-DD"`。「最近追加された問題」の並び順に使います |

**`answer` の書き方は 3 通り受け付けます**（他所から移植しやすくするため）:

- `0`〜`3` の数値インデックス ← **推奨**
- 正解の選択肢そのものの文字列（例 `"パーティションプルーニングが効く"`）
- `"A"`〜`"D"` の記号

### 章を増やしたいとき（任意）

8章以降を足すと、章名が未設定のため「第8章」とだけ表示されます。章名も付けたい場合は、配列の代わりにこの形も使えます（アプリは両方受け付けます）。

```json
{
  "chapters": { "1": "GCP の骨格", "8": "MLOps 入門" },
  "questions": [ { "id": 1, "chapter": 1, "...": "..." } ]
}
```

---

## 6. 章と理解度表（chapter / tag の対応）

`chapter` は **基礎知識ノート**（アーティファクト）の章番号にそのまま対応します。

| 章 | 基礎知識ノートの見出し | 問題数 |
| :-: | --- | :-: |
| 1 | GCP の骨格：プロジェクト・請求・API・IAM | 8 |
| 2 | BigQuery：置き場・ジョブ・課金の考え方 | 10 |
| 3 | 動かす側：Cloud Run Jobs・Artifact Registry・Scheduler・Secret | 7 |
| 4 | Terraform：宣言・state・plan・replace | 6 |
| 5 | データ基盤の考え方：層・冪等・as-of・品質・監視 | 8 |
| 6 | コストの3層（有料化後に効く） | 4 |
| 7 | このポートフォリオに当てはめると | 5 |

アプリ内では長いので「：」より前の短い名前（`GCP の骨格` など）で表示します。変えたい場合は
`index.html` の `DEFAULT_CHAPTER_TITLES` を書き換えてください。

### tag（理解度表の #）

現在使われているタグは `#1`〜`#20`（`#4` `#5` はまだ未使用）と、語のタグ
`as-of` / `品質` / `設計` の計21種です。

**tag は数字でなくても構いません。** `"#12"` のような番号でも `"as-of"` のような語でもよく、
数字だけを書いた場合（`"12"`）にのみ `#` を自動で補います。語のタグに `#` は付きません。

新しい観点を足したくなったら、既存の番号の続き（`#21`, `#22`, …）でも、
`冪等` のような語でも、好きな方で増やせます。アプリ側の変更は不要です。

## 7. 既存の `基礎クイズ.html` からの移植について

同名アーティファクトの `const Q=[...]` にあった **38問は移植済み**です。キー名は次のように対応させました。

| 基礎クイズ.html | quiz-data.json |
| --- | --- |
| `c` | `chapter` |
| `t` | `tag` |
| `q` | `q` |
| `o` | `options` |
| `a` | `answer` |
| `e` | `explanation` |
| （なし） | `id` … 1〜38 を採番 |
| （なし） | `addedAt` … 一律 `2026-08-30` |

`addedAt` は元データに無いため、既存38問はすべて同じ日付にしてあります。
これから追記する問題に当日の日付を入れれば、「最近追加された問題」モードで
新しいものから順に出るようになります。

## 7.5 出典について

**問題の内容は、必ず公式ドキュメントで裏を取ってください。** GCP は仕様がよく変わるため、
AI の記憶だけで作った問題は古い可能性があります。間違った内容を覚え直すのは、
覚えていないことより損です。

`source` に URL を入れると、解説の下にリンクが出ます。根拠の優先順位は次のとおりです。

1. Google Cloud 公式ドキュメント（`cloud.google.com` / `docs.cloud.google.com`）
2. HashiCorp 公式（Terraform）、Apache 公式（Airflow など）
3. Google Cloud 公式ブログ

個人ブログ・Qiita・Medium・Stack Overflow は根拠にしないでください（当たりを付けるのには使えます）。

`http://` `https://` 以外の URL はリンクにせず、文字列として表示するだけにしています。

### 出典の付与状況（48問すべて）

| 出典の種類 | 問題数 |
| --- | ---: |
| Google Cloud 公式ドキュメント | 30 |
| HashiCorp 公式（Terraform） | 4 |
| **方式設計書（構成・設計判断の問題）** | 7 |
| **基礎知識ノート（設計判断の問題）** | 4 |
| Terraform Registry / Docker / yfinance 公式 | 3 |

**11問だけ出典が自分のドキュメントを指しています。** 「raw 層の定義」「合成データを
使わない理由」「as-of ジョインで filed_date を使う理由」「dbt を mart だけに入れた判断」
「dev/prod を分けなかった判断」「Terraform の管理範囲」など、外部の公式ドキュメントに
答えが載っている類の問題ではなく、**あなた自身の設計判断**が根拠だからです。
無理に外部 URL を当てるより、ノート・設計書に戻れる方が正確です。

### Notion に足すときも出典を

「復習クイズ 問題ストック」に **`出典` 列**があります。URL を入れるとアプリに反映されます。

## 8. 学習履歴（localStorage と Notion）

学習記録は **localStorage が「正」**で、**Notion の「復習クイズ 学習記録」が同期先**です。

- 1セッション終わるごとに Notion へ1行書きます
- 起動時に Notion から取り込み、まだ送っていないセッションを送ります
- **オフラインでも解けます。**送れなかったぶんは次に開いたときに送り直します
- 端末をまたいで引き継がれます（PC で解いた記録がスマホに出ます）

突き合わせのルールは、**直近の正誤は新しい方を採用**、**出題回数・正解数は多い方を採用**（減らさない）です。
「間違いのみ」モードが見るのは直近の正誤なので、どの端末で解いても正しく反映されます。

ホームの「学習履歴をリセット」はこの端末のぶんだけを消します。Notion 側の行が残っていれば
次に開いたときに戻ってきます。完全に消すなら Notion の行も削除してください。

### 保存しているもの

| キー | 内容 |
| --- | --- |
| `gcpQuiz.v1` | 下の 5 項目 |
| `gcpQuiz.theme` | 表示テーマ（`auto` / `light` / `dark`） |

`gcpQuiz.v1` の中身:

| 項目 | 内容 | Notion と同期 |
| --- | --- | --- |
| `stats` | 問題ごとの `{seen, correct, wrong, last, lastAt, streak}`（4択の成績） | ✅ |
| `sessions` | 直近 200 件のセッション履歴（同期用の明細つき）。ホームに出すのは新しい 20 件だけで、残りは学習曲線を描くために持っています | ✅ |
| `explain` | 説明モードの自己申告 `{seen, ok, last, lastAt}` | ✅（明細に `%` 印） |
| `notes` | 自分で書いた説明（1問1件・1000字まで） | ❌ この端末だけ |
| `hidden` | 出題から外した問題の id | ❌ この端末だけ |

- 読み書きはすべて `try/catch` で囲んであります。プライベートモード等で `localStorage` が使えない場合はホームに警告を出し、**その場合もアプリはメモリ上の履歴で普通に動きます**（タブを閉じると消えるだけ）。
- Notion 連携が使えるときは **端末をまたいで共有されます**（上の突き合わせルール参照）。
  Notion に繋がらない環境では、その端末のブラウザに閉じます。
- 消したいときはホーム最下部の「学習履歴をリセット」から。
- `quiz-data.json` の問題を書き換えても、`id` が同じなら履歴は引き継がれます。**問題文を大きく直したときは id も変えると履歴がリセット**されて、まっさらな状態で解き直せます。

### バックアップ

`notes` と `hidden` は Notion に送っていないので、**ブラウザのデータを消すと消えます**。
ホームの「データ」→「**学習記録のバックアップ**」から、上の 5 項目をまとめて JSON で
書き出せます（問題そのものは入りません。それは `quiz-data.json` 側です）。

戻すときは同じ画面の欄に貼り付けて「この内容で復元する」。貼られた JSON は**通常の起動と
同じ検査**を通してから入るので、壊れた記録を貼ってもアプリが起動しなくなることはありません
（形式が違えば元の記録に戻します）。

> 「ファイルに保存」は、**アーティファクトとして開いているときは動かないことがあります**
> （claude.ai の枠がページ発のダウンロードを止めるため）。その場合は「コピー」を使ってください。

### ⚠️ Notion 連携と共有について（先に読んでください）

**このアーティファクトの URL は人に渡さないでください。**

アプリは Notion のデータソース ID をコードに直書きしています。これは「**開いた人の**
Notion 接続」に対して使われるので、同じ Notion ワークスペースの人に URL を渡すと:

- その人が解いたセッションが、**あなたの**「復習クイズ 学習記録」に書き込まれます
- **あなたの**全学習履歴（学習時刻・頻度・問題ごとの正誤）が、その人の端末に取り込まれます

ワークスペースが違う相手なら権限エラーが出るだけで無害ですが、レビューしてもらうつもりで
渡すと事故ります。見せたいときは画面のスクリーンショットにしてください。

**Notion に送っているもの / 送っていないもの**

| 送っている | 送っていない |
| --- | --- |
| 日時（ミリ秒精度）、モード名、出題数、正解数、正答率、`問題id:正誤` の明細（説明モードは `%` 印つき） | 問題文、選択肢、解説、出典、**自分で書いた説明メモ**、出題から外した問題 |

この DB を見られる人には、**いつ・どれくらいの頻度で勉強したか、どの問題を何回間違えたか**
が分かります。ワークスペースを共有する判断をするときは、そこを踏まえてください。

**リポジトリは public です。** Notion のビュー URL・データソース ID と、
出典に使っている claude.ai アーティファクトの URL がコードに入っています。
いずれも資格情報ではなく、それ単体では中身を読めません。ただし
**当該の Notion DB で「ウェブに公開」を絶対にオンにしないでください** — ID がそのまま
公開 URL になり、その ID は既に GitHub 上で誰でも見られます。

### 学習の記録（推移）

ホームの「最近のセッション」から **「学習の記録（推移）を見る」** に入ると、伸びの推移が出ます。
新しく記録している項目はありません。**すでにある明細（`@<日時>|<id>:1,...`）を古い順に読み直して**
組み立てているだけなので、過去に解いたぶんもそのままグラフに載ります。

| 指標 | 意味 |
| --- | --- |
| **カバー率** | 一度でも正解できた問題の割合。単調に増えるので「どこまで手が届いたか」の記録になる |
| **定着率** | いま「直近正解」の状態にある割合。忘れると下がるので、復習どきの目安 |
| **方式別の定着** | 方式ごとの定着率の推移。方式設計書のどこが言葉にできて、どこがまだかが見える |

> **正答率の推移はあえて出していません。** このアプリは間違えた問題を優先して出すので、
> 上達するほど難しい問題ばかりが並び、正答率は上がりません。学習曲線として一番描きたくなる
> グラフが、この設計では一番誤解を生みます。伸びは上の2本で見てください。

分母は**いまある問題数**で固定しています。あとから問題が増えるため、当時の問題数で割ると
過去の値が実際より高く出てしまうからです。同じ理由で、削除した問題の記録は数えません。

保存件数の上限（200件）を超えて古い履歴が落ちると、曲線の左端は実際より低く出ます。
その場合は画面下に断り書きが出ます（見出しの数字は `stats` から取るので常に正しい値です）。
